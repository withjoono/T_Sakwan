# 제품 범위와 방향

## 범위

사관학교(육사·해사·공사·국간사)·경찰대 준비생용 플랫폼.
T스쿨 생태계의 기존 앱을 **사관/경찰 시험에 맞게 변형**해 묶는 것이 기본 구조다.

| 구성 | 원본 앱 | T사관에서의 형태 |
|---|---|---|
| 플래너 | T스쿨 StudyPlanner | 사관·경찰 일정(5월 경찰대 접수, 8.1 1차 등)에 맞춘 플래너 |
| 모의고사(모고) | Mogo | 사관·경찰 문제 형식 전용 회차·채점·1차 합불예측 (→ `mock-and-onecha.md`) |
| 생기부 | 생기북 앱 | 사관·경찰형 생기부 설계 |

- 자체 백엔드는 두지 않는다. 서버 로직은 mogo-backend 또는 Hub 백엔드에 붙인다(AGENTS.md 규칙).

## 방향 — 사관 AI 에이전트 (2026-10 구상 단계, 미확정)

- 사관 사이트 하나를 **"사관 AI 에이전트"** 로 만들려는 구상이 있다.
- 로그인하면 **대시보드에 앱(플래너·모고 등)이 나오는 방식**을 검토 중. 프로모 페이지·사관 플래너·사관 모고의 관계를 이 관점에서 재정리할 예정.
- 아직 설계 확정 전이므로, 이 방향과 충돌하는 큰 구조 변경(라우트 체계 개편 등)은 사용자 확인 후 진행한다.

## 작업 순서 원칙

- 새 페이지군은 **기획서 먼저 → 사용자 확인 → 코드** 순서로 간다. (입시정보 페이지가 이 순서로 만들어짐: `docs/admission/기획서-v2.md` → 구현)
- 기획과 구현이 달라지면 구현 노트에 **왜 바꿨는지**를 남긴다(예: 주제별 8 → 대학별 5 전환, `docs/admission/대학별-페이지-구현노트.md`).

## 전환 목표 3가지 (정보 페이지 공통)

1. T사관 전용 모의고사 응시
2. Hub 회원가입 → 마이클래스(`/class/*`) 합류
3. 멘토링·1:1 상담 문의 (기존 카톡 상담 채널과 연결)

CTA 원칙(페이지당 1개, 정보를 다 준 뒤 배치, 로그인 벽·가림 금지)과 상담 폼 수집 항목 제한(이름·연락처·목표 학교·학년까지, **성적·건강 정보는 받지 않음**)은 `docs/admission/기획서-v2.md` §9에 있다.
